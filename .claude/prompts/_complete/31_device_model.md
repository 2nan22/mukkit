# 31_device_model — 글에서 가게 찾기 · 기기 안 모델로 더 꼼꼼하게 (선택)

## 0. 진입 전 필수
- 규칙 파일을 먼저 읽는다 · `git checkout dev && git checkout -b feat/31_device_model`
- 사용자 결정 원문 (2026-11-23): "선택이 나으려나 그리고 지금은 크롬 앱이라 그렇고 네이티브 앱 형식으로 하면 좀 낫지 않을끄" → 웹에 선택 기능으로, 네이티브는 출시 준비 때 기기 내장 모델로 갈아 끼우기 · "그렇게해"

## 1. 세션 목표 (성공 기준)
- 실기기 시험 (2026-11-22 · 갤럭시 S23 FE · Chrome 157 · Gemma 4 E2B, LiteRT-LM Web 0.19.0) — 시험 글 16개 · 정답 21곳
    - 모델 맞음 17 · 놓침 4 · 틀린 후보 0 · 한 글 가운데 3.8초 · 올리기 11.4초 / 규칙 맞음 11 · 틀린 후보 3
- 규칙 약점 두 가지 보완 — 번호 · 대시 목록 줄 뒤 설명(' - 빵 맛집' · ': 스콘 필수') · 줄 중간 📌 · 영상 시간표(00:42) → 시험 글 규칙 맞음 11 → 15 이상
- '더 꼼꼼하게 찾기' 선택 기능 — 되는 기기(WebGPU)에서만 보이고, 받은 사람만 모델로 읽어 규칙 결과와 합친다
    - 글은 기기 밖으로 나가지 않는다 (모델 · 실행 모두 기기 안) · 서버에는 지금처럼 이름 · 주소만
    - 모델이 실패하면 규칙 결과로 계속 (기능이 막히지 않음)
    - 모델 지우기로 공간을 돌려받을 수 있다

## 2. 추상화 전략
- 교체 지점 `DevicePlaceReader` — `supported()` · `saved()` · `download()` · `remove()` · `readNames(text)`. 지금 구현은 Gemma 4 E2B + LiteRT-LM Web(WebGPU), 네이티브로 감싸면 Gemini Nano · Apple 기본 모델 구현으로 이 파일만 바꾼다
- 모델 답 풀기 · 규칙 후보와 합치기는 `domain/textPlaces.ts` 의 순수 함수 (시험 가능)
- 모델 파일은 저장소 커밋 고정 URL · Cache API 에 직접 저장 (엔진에 캐시 없음, 폰에서 검증한 방식)
- 실행 라이브러리는 npm `@litert-lm/core@0.19.0`, wasm 은 라이브러리 기본 경로(jsDelivr)

## 3. 진행 현황
```
✓ ### 1. 규칙 보완 + 모델 답 풀기 · 합치기 순수 함수 → 검증: 단위 시험 · 시험 글 규칙 점수
✓ ### 2. 기기 모델 모듈 + 글에서 가게 찾기 화면 선택 기능 → 검증: tsc · lint · 브라우저(맥 Chrome WebGPU) 실제 받기 · 찾기 · 지우기
✓ ### 3. UX 검토 반영 · 캡처 → 검증: Fable 검토 · 구현 화면 아티팩트
```

## 4. 범위 밖
- 네이티브 앱 감싸기 · 기기 내장 모델(Gemini Nano · Apple) — 출시 준비
- 추천 · 약속에 모델 쓰기 — 이번 결과를 본 뒤 따로
- 받기를 백그라운드로(Background Fetch) — 화면을 켜 둔 채 받기만
