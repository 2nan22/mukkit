## 1. 세션 목표 (성공 기준)
- **모든 화면 41개**를 실제로 띄워(390px · 로그인 상태 · 데이터 있는 상태와 빈 상태) 캡처하고, 화면마다 최소 한 번 네 팀의 눈을 거친다
- 네 팀 에이전트가 각자 관점으로 검토 → 겹치는 지적은 합치고 **우선순위(P0 고장 · P1 사용성 · P2 다듬기)** 를 매긴 한 장의 목록
    - 항목마다: 화면 · 문제 · 근거(캡처 또는 file:line) · 제안 · 예상 크기(S/M/L) · 담당 팀
- P0 는 이번 세션에서 재현까지 확인(재현 안 되면 P0 에서 내림)
- 결과물: 사용자에게 보여 줄 **QA 보고서 아티팩트** 1개(화면 캡처 + 목록) · 고칠 일을 묶은 다음 세션 prompt 초안(57_ ~)
- 이 세션은 **고치지 않는다** — 1줄짜리 오타 · 문구 정도만 예외로 바로 고치고 따로 커밋

## 2. 추상화 전략 (검토 방법)
- 화면을 6구역으로 나눠 구역마다 같은 틀로 검토한다
    | 구역 | 화면 |
    |---|---|
    | A 시작 · 가입 | `/` · `/onboarding/nickname` · `/onboarding/terms` · `/onboarding/import` · 로그인 왕복 · `/auth/*` 오류 |
    | B 홈 · 피드 · 알림 · 찾기 | `/home` · `/feed` · `/notifications` · `/eat` · `/search` |
    | C 지도 · 장소 · 평가 | `/map`(내 장소 · 팔로잉 · 등급/리스트 보기) · `/p/[placeId]` · `/p/[placeId]/r/[userId]` · `/rate` · `/rate/[placeId]` · `/rank` |
    | D 리스트 · 가져오기 · 공유 | `/lists`(리스트 · 등급) · `/lists/[listId]` · `/lists/new` · `/lists/popular` · `/l/[listId]`(비로그인) · `/import` · `/import/sources` · `/import/text`(숨김 — 노출 여부만) |
    | E 사람 · MY · 설정 · 약관 | `/my` · `/my/edit` · `/u/[userId]` · `/people` · `/settings` · `/settings/accounts` · `/settings/notifications` · `/settings/blocked` · `/terms` · `/privacy` |
    | F 약속 · 함께 방문 | `/meet` · `/meet/new` · `/meet/[meetupId]` · `/meet/[meetupId]/visit` · `/m/[token]`(초대 링크) · `/visits` |
- **네 팀 에이전트** (병렬, 같은 캡처 · 같은 화면 목록을 받는다. 서로의 결론은 주지 않는다 — 독립 판단)
    - **디자인팀**: 시각 위계 · 일관성(간격 · 글자 · 색 규칙: 주황은 화면당 주 버튼 하나, 선택은 검정) · 아이콘 · 빈 상태 · 다크/작은 화면 · 접근성(44px · 대비 · 포커스)
    - **기능(QA)팀**: 실제로 눌러 보며 흐름 끊김 · 뒤로가기(`docs/navigation.md` 점검표) · 오류 · 로딩 · 빈/많은 데이터(1000곳 넘는 사용자) · 비로그인 · 차단 · 권한 거부 · 홈 화면 앱(PWA)
    - **기획팀**: 핵심 루프(가져오기 → 지도 → 평가 → 공유 · 팔로우)가 끊기는 곳 · 비협상 목표(가게 레버 없음 · 가게 평균 점수 없음) 위반 여부 · 문구 말투(해요체 · AI 같은 말 · 센 말) · 기능이 사용자에게 발견되는지
    - **개발팀**: 코드 기준 — 숨은 고장(행 수 제한 1000 · 경쟁 상태 · 캐시 · RLS · 서버 전용 쓰기) · 성능(화면당 조회 수 · 카카오 SDK) · 보안 · 죽은 코드 · 테스트 빈 곳
- 캡처는 Playwright/브라우저 패널로 390×844 · 로그인 쿠키는 로컬 시험 계정(매직 링크 → `verifyOtp` → `sb-127-auth-token` 쿠키) — 실제 계정 · 운영 데이터는 쓰지 않는다
- 겹침 정리 · 우선순위는 메인 세션이 한다(에이전트 결론을 그대로 붙이지 않고 캡처 · 코드로 확인한 것만 남긴다)

## 3. 진행 현황 (꼭지 = 커밋 단위)
```
### 1. 시험 데이터 · 캡처 준비 → 검증: 로컬 시험 계정 3명(많이 저장 · 막 가입 · 팔로잉 있음)으로 41개 화면이 데이터 있는 상태로 열림
    - 계정 A: 가져온 원본 3개 · 1000곳 넘게 · 등급 고루 · 사진 몇 장 · 리스트 · 3숟가락 순위
    - 계정 B: 막 가입(빈 상태 · 온보딩)
    - 계정 C: A 를 팔로우 · 댓글 · 좋아요 · 약속 · 함께 방문
    - 시드 스크립트는 scripts/ 에 두되 실제 개인 데이터 · 비밀값 없이 (커밋 가능한 가짜 데이터만)
### 2. 화면 캡처 아티팩트 → 검증: 구역 A~F 전 화면 + 빈 상태 · 오류 상태 캡처가 한 페이지에
### 3. 네 팀 검토 (구역별 병렬) → 검증: 팀 × 구역 결과가 모두 모임 · 근거 없는 항목은 버림
### 4. 통합 목록 · P0 재현 → 검증: P0/P1/P2 목록 · P0 재현 결과 · 겹침 정리
### 5. QA 보고서 아티팩트 · 다음 세션 prompt 초안 → 검증: 사용자에게 보고서 링크 · 57_ ~ prompt 파일(묶음 단위)
```
