# 15_visit_together — 함께 방문한 기록 (누구랑 · 각자 평가)

## 0. 진입 전 필수
- 규칙 파일 · 디자인 시안(방문 기록 아트보드가 없으면 '시안 없음'으로 밝힘)
- `git checkout dev && git pull && git checkout -b feat/15_visit_together`
- **시작 전에 사용자에게 정할 것** (아래 표) — 답을 받기 전에는 1번 꼭지를 시작하지 않는다
- 14(약속 잡기)와 독립 — 순서 무관. 14가 먼저 끝났으면 '약속 → 방문 기록' 연결을 4번 꼭지에 추가

## 1. 세션 목표 (성공 기준)
- 평가 화면에서 **함께 간 사람**을 고를 수 있다 (마이슐랭 사용자 · 사용자가 아닌 사람은 이름만 메모)
- 태그된 사용자는 **수락해야** 기록에 이름이 보인다 — 수락 전에는 작성자에게만 보임
- 수락한 사람은 같은 방문에 **자기 등급(3 · 2 · 1스타 등)과 한 줄 평가**를 따로 남긴다 — 평균을 내지 않고 나란히 보여 준다
- 장소 상세 · 프로필에 '○○님과 함께' 방문 묶음이 보인다 (각자의 공개 범위를 따름)
- 등급은 기존 tier 그대로 쓴다 — 별도의 별점 척도를 새로 만들지 않는다
- pgTAP: 수락 전 태그는 남에게 안 보임 · 남의 평가를 대신 못 씀 · 공개 범위 준수

## 2. 추상화 전략
- `visits`(장소 · 날짜 · 만든 사람) + `visit_members`(사용자 또는 이름 메모 · 상태 invited/accepted/declined)
- 각자의 평가는 지금처럼 `user_places` 에 두고, 방문은 그 평가들을 **묶기만** 한다 — 평가 저장 경로를 두 개로 만들지 않는다
- 공개 읽기는 기존처럼 security definer 함수(칸을 고른)로만 — 메모는 언제나 본인만

## 3. 진행 현황
```
### 1. visits · visit_members · RLS · 수락 흐름 함수 · pgTAP → 검증: 수락 전 노출 0건
### 2. 평가 화면 '함께 간 사람' 고르기 · 이름 메모 → 검증: 저장 · 수정 · 삭제
### 3. 받은 태그 수락 · 거절 (MY 또는 피드 알림 칸) · 내 등급 남기기 → 검증: 두 계정 왕복
### 4. 장소 상세 · 프로필 · 피드에 방문 묶음 표시 · 캡처 아티팩트
```

## 정할 것 (세션 시작 때 사용자에게)
| 질문 | 기본안 |
|---|---|
| 누구를 태그할 수 있나 | 서로 팔로우한 사람 + 사용자가 아닌 사람은 이름 메모(나만 보임) |
| 태그 수락 | 필수 — 수락 전에는 내 기록에만 보임 |
| 방문 묶음을 남이 볼 때 | 각자 평가의 공개 범위를 따름 (내 평가가 '나만'이면 묶음에서도 내 칸은 숨김) |
| 피드 표시 | '○○님이 △△님과 방문' 한 줄 (둘 다 공개일 때만) |

## 4. 범위 밖
- 좋아요 · 댓글 · 사진 공동 앨범
- 방문 인증(영수증 · 위치) — 별도 논의
- 평균 · 합산 점수 (비협상 목표 2)
