## 1. 세션 목표 (성공 기준)
- 내가 올린 사진이 있는 가게는 **나에게** 그 사진이 대표 이미지로 보인다 — 장소 상세 상단 · 내 장소 목록 행 썸네일
- 네이버 · 카카오 가게 사진은 가져오지 않는다 (결정 기록: 저작권 · 약관) — 사진이 없으면 지금처럼 지도 · 업종 아이콘
- 프로필의 평가 수는 실제 전체 수, 리스트 수는 보는 사람 기준으로 맞게 (본인은 전체 · 남은 공개만, 문구로 구분)
- 주요 화면(홈 · 지도 · 장소 상세 · 프로필) 서버 응답 시간을 측정해 **개선 전후 수치**를 남긴다 — 목표: 각 화면 p50 30% 이상 단축

## 2. 원인 (조사 완료 · 2026-11-22)
- 평가 60곳: `src/app/u/[userId]/page.tsx:63,105` 가 `ratings.length` 를 표시 — `profile_ratings` 기본 `p_limit 60` 에 잘림. 같은 화면의 `profile_stats` 합계(page.tsx:50)가 정답
- 리스트 수: 프로필은 `profile_lists`(공개 리스트만, `20261121180000_taste.sql:68`), 새 리스트 기본값은 비공개 → 만들어도 0. MY 는 전체를 세서 두 화면이 다름
- 사진: 외부 사진을 가져오는 코드 없음(메뉴만). 내 사진은 `rating_media` + 서명 주소 `getMyMedia`(`place.ts:102`). `PlaceRow` 에 이미지 자리 없음 · `PlaceHeaderMap` 은 지도만
- 느림 후보: 장소 상세 순차 await + 카카오 메뉴 조회가 페이지 전체를 막음(Suspense 없음) · 홈 카운트 쿼리 2개 순차 · `getMyWantToGoPoints` limit 2000 · 지도 `getMyMapPlaces` 무제한 조인 · 핀 선택 때 오버레이 전체 재생성 · 프로필의 사진 서명 매 요청

## 3. 추상화 전략
- 대표 이미지: `my_place_covers(place_ids)` 처럼 내 첫 사진 경로만 돌려주는 한 번의 조회 → 서명은 화면에 보이는 것만 일괄. `PlaceRow` 에 `thumb?` 하나 추가 (없으면 업종 아이콘)
- 숫자: 표시는 집계 함수 값만 쓰고 목록 길이를 숫자로 쓰지 않는다
- 속도: 측정 먼저 — 화면별 서버 시간 로그(`Server-Timing` 또는 dev 로그) 기준선 → 병렬화 · 느린 외부 호출은 Suspense 로 분리 · 큰 조회는 필요한 칸 · 개수만 → 같은 방법으로 재측정

## 4. 진행 현황
```
### 1. 프로필 평가 수 · 리스트 수 바로잡기 → 검증: 61곳 이상 계정에서 실제 수 · 비공개 리스트 만든 뒤 본인 화면 반영
### 2. 내 사진 대표 이미지 — 장소 상세 상단 · 내 장소 목록 썸네일 (나에게만) → 검증: 사진 있는/없는 가게 캡처 · 남의 계정에선 안 보임
### 3. 반응 속도 기준선 측정 (홈 · 지도 · 장소 상세 · 프로필, 각 10회) → 검증: 수치 표
### 4. 병렬화 · 메뉴 Suspense 분리 · 큰 조회 줄이기 · 핀 재생성 줄이기 → 검증: 같은 방법 재측정, 30% 이상 단축
```
