# 32 — 장소 만들기를 서버 전용으로

## 목표
- 로그인 사용자가 places · place_sources 에 직접 행을 넣거나 고칠 수 없다 → 검증: pgTAP 42501
- 가져오기 · 검색으로 새 가게 열기 · 자동 새로 고침은 그대로 동작 → 검증: 로컬 DB 검사 · 화면에서 새 가게 열기

## 배경
places · place_sources 의 insert 정책이 with check (true) 이고 upsert 가 ignoreDuplicates 라
실제 가게 id 로 가짜 이름 · 좌표를 먼저 넣으면 이후 가져오는 사람이 그 행을 썼다.

## 추상화
장소를 만드는 길은 upsertPlaces 하나 — 이 함수만 서비스 키 클라이언트로 쓴다.
넘어오는 값은 서버가 네이버 · 카카오에서 직접 받았거나(가져오기 · 새로 고침) 카카오로 다시 확인한 것(검색 · 글에서 찾기).

## 진행 현황
1. [x] 마이그레이션 — 두 insert 정책 삭제 · anon · authenticated 의 insert · update · delete 회수
2. [x] upsertPlaces 서비스 키 사용 · 호출처 인자 정리 · 검사 준비를 서비스 키로
3. [x] 검사 — pgTAP 164 · 로컬 DB 18 (3회 연속) · 단위 95 · 화면에서 검색 결과 새 가게 열기

## 범위 밖
- 서비스 키가 없는 환경(키 누락)에서는 장소를 못 만든다 — 운영은 크론과 같은 키라 이미 있음
