# 14_meetup_spots — 다른 사용자와 약속 잡기 (중간 지역 · 목적별 추천)

## 0. 진입 전 필수
- 규칙 파일 · 디자인 시안(약속 관련 아트보드가 없으면 '시안 없음'으로 밝히고 기존 화면 문법을 따른다)
- `git checkout dev && git pull && git checkout -b feat/14_meetup_spots`
- **시작 전에 사용자에게 정할 것 (아래 '정할 것' 표)** — 답을 받기 전에는 1번 꼭지를 시작하지 않는다

## 1. 세션 목표 (성공 기준)
- 팔로우 관계인 사람에게 약속을 제안하고, 두 사람이 각자 **출발 지역**을 넣으면 함께 가기 좋은 **지역 3곳**과 지역마다 **가게 3~5곳**을 보여 준다
- 목적(가벼운 식사 · 회식 · 데이트 · 술 · 카페)에 따라 음식 종류 · 분위기 가중치가 달라진다
- 추천 이유를 보여 준다: 예 '두 분 모두 30분 안팎' · '상대가 3스타 준 곳' · '둘 다 저장한 곳' — **가게 평균 점수는 만들지 않는다**
- 개인정보: 집 주소를 저장하지 않는다. 출발 지역은 **역 · 동 단위**로만, 좌표는 소수 2자리(약 1km)로 깎아 저장하고 **상대에게도 보이지 않는다** (보이는 것은 추천 결과뿐)
- 약속이 끝나면(또는 14일 뒤) 출발 지역 기록을 지운다 — 새벽 크론에 정리 작업 추가
- pgTAP: 약속 당사자 둘만 읽기 · 상대의 출발 지역은 상대도 못 읽음

## 2. 추상화 전략
- `MeetupPlanner` — 입력(두 출발 지점 · 목적) → 후보 지역 → 지역별 가게. 지역 후보는 처음엔 **주요 역 · 상권 목록(정적 데이터) + 두 사람 기록이 많은 지역**, 이동 시간은 처음엔 직선거리 근사
- 이동 시간 공급자 인터페이스 `TravelTime` — 직선거리 근사 구현으로 시작, 대중교통 API(ODsay 등)는 키가 생기면 구현체만 추가
- 가게 고르기는 기존 `eatScore`(여기서 뭐 먹지)를 두 사람 취향으로 확장 — 한쪽 취향만 맞는 곳보다 둘 다 맞는 곳을 위로
- '핫한 곳'은 외부 인기 순위를 쓰지 않는다 — 마이슐랭 안의 최근 평가 · 저장이 몰린 지역으로 (비협상 목표 1 · 외부 리뷰 수집 금지)

## 3. 진행 현황
```
### 1. meetups · meetup_origins 테이블 · RLS · pgTAP → 검증: 당사자 외 접근 0건, 상대 출발 지역 읽기 0건
### 2. MeetupPlanner (지역 후보 · TravelTime 근사 · 두 사람 취향 점수) · 단위 테스트 → 검증: 고정 입력에 지역 3곳 · 이유 문구
### 3. 약속 만들기 · 초대 받기 · 출발 지역 입력 화면 → 검증: 두 계정으로 왕복
### 4. 추천 결과 화면(지도 + 지역별 가게 + 이유) · 크론 정리 작업 · 캡처 아티팩트
```

## 정할 것 (세션 시작 때 사용자에게)
| 질문 | 기본안 |
|---|---|
| 누구와 약속을 잡을 수 있나 | 서로 팔로우한 사람만 (모르는 사람 초대 막기) |
| 출발 지역 입력 방식 | 역 · 동 검색해서 고르기 (현재 위치 한 번 쓰기도 허용, 저장은 동 단위) |
| 이동 시간 | 우선 직선거리 근사 — 대중교통 시간은 API 키 확보 후 |
| 알림 | 앱 안 표시만 (푸시 · 카카오톡 알림은 범위 밖) |

## 4. 범위 밖
- 채팅 · 일정 투표 · 캘린더 연동 · 푸시 알림
- 셋 이상 다자간 약속 (구조는 확장 가능하게 두되 화면은 둘만)
- 외부 인기 순위 · 리뷰 크롤링
