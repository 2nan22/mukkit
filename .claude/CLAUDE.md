## 프로젝트 개요

**마이슐랭(가칭)** — 사람 단위로 신뢰하는 장소 평가 · 리스트 공유 모바일 웹.
네이버 · 카카오 지도 리뷰가 리뷰 이벤트로 오염됐다는 문제의식에서 출발한다.

- 네이버 지도 공유 리스트를 가져와 첫 화면부터 지도가 채워진 상태로 시작
- 등급: 3스타 · 2스타 · 1스타 · 추천 안 함 · 가고 싶은 곳 · 평가 전
- **평가는 선택** — 저장만 해도 지도 · 리스트를 다 쓸 수 있다. 평가는 신뢰 통계 · 추천의 재료
- 리스트 공유(비로그인 열람) · 팔로우 · 취향 겹침 기반 사람 추천 · 3스타 비교로 등급 안 순위

### 비협상 목표
1. **가게가 쓸 수 있는 레버를 두지 않는다** — 업주 답글 · 리뷰 요청 · 노출 광고 없음. 협찬 표시 평가는 통계 제외
2. **가게 단위 평균 점수를 만들지 않는다** — 누가 어떤 등급을 줬는지만 보인다. 점수를 사도 효과가 없어야 한다

### 결정 기록 (근거는 Vault)
- 이름 '마이슐랭' · 등급 '3스타' 표기는 가칭 — 미쉐린 상표 리스크로 **공개 출시 전 재검토**, 이름과 등급 표기는 함께 바꾼다
- 네이버 가져오기 — 공개 범위 '일부 공개' · '전체 공개' 리스트의 공유 링크로 로그인 없이 수집 (비공식 내부 API)
- 음식 종류 — 네이버 `cidPath` 코드 또는 카카오 로컬 API 카테고리
- 지도 SDK — 카카오맵 JavaScript SDK (ADR 0001 변경 이력) · 무료 쿼터는 마이슐랭 카카오 앱 · 키 NEXT_PUBLIC_KAKAO_MAP_KEY
- 로그인 — 카카오 · 구글 · 네이버 로컬 실제 왕복 확인 (2026-11-20)
    - 네이버는 커스텀 OIDC `custom:naver` — `pnpm auth:naver` 로 등록 (ADR 0002)
    - 첫 로그인은 닉네임 정하기 화면을 거침 · 닉네임 중복 금지(대소문자 무시)
    - 카카오는 Supabase 가 account_email 을 항상 요청 — 비즈 앱 전환 + 이메일 동의항목(선택) 필수, 안 하면 KOE205
- 같은 사람의 여러 소셜 계정은 설정 › 로그인 연결로 묶음 (수동 연결) — 연결할 때마다 계정을 다시 고르게 함
- 가져오기 — 리스트마다 '그냥 저장한 리스트(리스트로 · 평가 전)' / '등급 리스트(고른 등급, 리스트 안 만듦)'
    - 네이버 메모는 본인만 보는 메모로 · 다시 가져와도 마이슐랭에서 고친 등급 · 메모는 유지
    - 폐업 여부(places.available)는 저장만, 주기적으로 다시 확인해 갱신하는 작업은 이후
- 여기서 뭐 먹지 — 지역 · 위치 기준으로 내 기록 · 팔로잉 · 취향 비슷한 사람의 평가를 업종별로 묶어 추천, 추천 이유를 보여주고 가게 평균 점수는 만들지 않는다 (11)
- 리스트는 등급과 무관하게 자유롭게 — 저장한 곳으로 지역 · 테마 리스트를 직접 만든다 (07)
- 같은 가게를 네이버 · 카카오에 모두 저장하면 장소 하나로 합친다 — 50m 안 + 이름 일치 (06)
- 가져온 원본(리스트 이름 · 메모 · 업종 · 원본 응답)은 출처 · 리스트별로 imported_items 에 그대로 보관 — 분류 · 리스트 만들기의 원천 데이터
- 등급 설명은 '찾아갈 만한 정도'로 — 3스타 일부러 멀리 찾아갈 만한 곳 · 2스타 자신 있게 권하는 곳 · 1스타 근처라면 가볼 만한 곳
- 로컬 DB 초기화(`pnpm db:reset`)는 계정이 지워지므로 사용자에게 먼저 묻는다 — 새 마이그레이션은 `supabase migration up --local`
- 카카오맵 가져오기 — 공개 즐겨찾기 폴더를 링크로 로그인 없이 수집 (비공식 내부 API) · 구글은 테이크아웃 파일 올리기만 가능
- 세션마다 만든 화면은 캡처해 아티팩트로 보여준다 — 구현 화면: https://claude.ai/artifact/NE63w4wZti9HEqmFUBLW11
- 장소 사진 — 네이버 · 카카오 장소 페이지의 사진은 가져오거나 링크로 띄우지 않는다 (저작권 · 약관). 원문 링크 · 사용자가 직접 올린 사진만
- 평가에 사용자가 찍은 사진 · 영상을 올릴 수 있고, 공개하면 팔로우하는 사람 피드에 보인다 (09~)
- 화면 · 문구에 AI 같은 이모지를 쓰지 않는다 · 카카오 · Google · 네이버는 공식 로고 · 버튼 가이드대로
- 남의 저장 · 메모는 직접 읽기 불가 — 공개 읽기는 public_list 처럼 칸을 고른 security definer 함수로만
- 평가의 한 줄 평가(review)는 공개 범위대로, 메모(note)는 언제나 나만 · 사진은 경로 <사용자>/<장소>/ 로 Storage 정책이 평가 공개 범위를 따른다
- 배포 시 매일 새벽 외부 크론(Vercel Cron 또는 GitHub Actions)이 폐업 여부 확인 작업을 돌리고 실행 기록을 DB 에 남긴다 — Supabase 무료 플랜 비활성 정지 방지 겸용
- 로컬 Supabase 는 Storage 포함해 기동 (`pnpm db:start`)
- 로컬 Supabase 는 553xx 포트 — 다른 로컬 Supabase(티키타카)와 충돌 회피
- 뒤로 · 닫기는 공용 AppHeader · useLeave — 앱 안에서 왔으면 history back, 바로 열었으면 상위 화면 replace. 저장 후 이동도 같은 방식(기록에 폼을 남기지 않음)
- 용어: 리스트는 '담기', 그 밖에 추가 · 삭제 · 선택 · 키워드. 설명 문장은 한 줄 · 한 가지
- MY 에는 리스트 목록을 두지 않음 — 리스트는 리스트 탭 하나로 (시안 MY 와 다름, 사용자 결정 2026-11-22)
- 브랜드 색 #c8410b — 화면당 주 버튼 하나만, 선택 칩 · 진행 막대는 검정. 제안값 #d9480f 는 흰 글자 대비 4.3:1 이라 한 단계 진하게 · 3스타는 주황과 겹치지 않게 빨강 #b42330
- 디자인 시안: https://claude.ai/artifact/WNsn9Zu7nGyQxdQxpUXc2n — 화면을 만들 때 해당 아트보드를 먼저 열고 그 구성을 따른다 (홈을 피드로 바꿨다가 되돌린 일 있음)

## 베이스 대비 변경 (개인 프로젝트)
- `harvest-worklog` skill 제외 — 회사 업무일지 환원 대상 아님
- 자막 생태계 서술 무시 — 도메인이 다르다
- Git — 개인 계정 `2nan22` 로 커밋하고 `git push` 로 올린다. **`gh` 로 PR · 머지하지 않는다**
    - `git_workflow.md` 의 PR 단계는 로컬 `git merge --no-ff` 후 push 로 대체 (feat → dev, dev → main)
    - **커밋 · 머지 · push 는 묻지 않고 진행** — 꼭지마다 커밋하고 메시지는 보고에만 남긴다 (베이스의 '승인 후 다음 꼭지' 대체)
    - 커밋 · 머지 메시지에 `Co-Authored-By` 등 트레일러를 넣지 않는다 (Vault 저장소 규칙과 동일)
    - dev → main 은 마일스톤 단위로만, 사용자가 요청할 때
- 비밀값뿐 아니라 개인 데이터 · 노출이 우려되는 파일(실제 장소 메모 · 공유 링크)도 커밋 금지 · `.gitignore`
