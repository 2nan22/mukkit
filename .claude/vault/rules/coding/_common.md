# coding/_common.md — 언어 공통 코딩 원칙

> 언어와 무관하게 모든 코드에 적용. 언어별 세부는 같은 폴더의 `python.md`·`fastapi.md`·`react.md`·`html-css.md` 등을 함께 읽는다. **여러 개에 걸치면 여러 개를 읽는다.**
> 프로젝트가 쓰는 언어의 파일만 읽으면 된다(예: 백엔드만이면 `python.md`).

## 핵심 원칙
- **DRY & Modularity**: 공통 로직은 공용 모듈/유틸 또는 base class로 분리해 재사용성 극대화.
- **단일 책임(SRP)**: 한 파일·함수·컴포넌트에 하나의 책임. 여러 책임 응집 금지.
- **명확한 네이밍**: 모호한 약어 회피. 의도가 드러나는 이름.
- **외과적 변경**(CLAUDE.md 행동 지침 §3): 깨지지 않은 것을 리팩터 금지, 본인 변경 흔적만 청소.
- **silent fallback 금지**: 품질 저하를 동반하는 자동 강등(모델·정밀도)뿐 아니라 **설정·요청
  항목이 조용히 기본값으로 떨어지는 것**도 포함한다. 모르는 항목은 **거절하거나, 최소한 "무시했다"를
  응답·로그에 남긴다**(무조건 거절은 구버전이 신버전 요청을 못 받게 만든다). 폴백이 일어났으면
  **실제로 쓴 것을 결과에 담는다**.

## 주석 — 기본 1줄
> 코드는 **읽을 때마다** 값을 치르는 자리다. 같은 설명을 코드·문서·위키 세 곳에 두지 않는다.

- **기본 1줄.** 그 코드가 **무엇을 왜** 하는지 한 문장.
- **2줄은 예외로만** — 그 값을 바꾸면 무엇이 깨지는지 막아야 할 때. 근거 자체는 문서·위키에 두고
  주석은 **가리키기만** 한다. 예: `# 잡 1건 피크 기준. 조정 기준은 README '디스크 가드' 절.`
- **3줄 이상 금지.** 더 길어야 한다면 둘 중 하나다 — 코드가 복잡한 것이니 **고치거나**,
  문서로 갈 내용이니 **옮긴다**.
- **금지** — 세션 번호 · 날짜 · 결정 id · *이전에는 X였다* · 변경 이력 · 표 · 구분선(`# ─────`).
  경위는 **커밋 메시지와 세션 prompt** 가 진다. 지운 코드의 이유도 주석이 아니라 커밋에 적는다.
- 살아남는 것은 **"왜 반대로 안 했나"** 다. 그것이 없으면 다음 사람이 같은 함정을 다시 밟는다 —
  단, 그 이유도 한 줄로 닫는다.

```python
# ❌ 심각도 3단계다 (세션 25). 21 이 예고한 조건 — 운영에서 갈릴 때 — 가 충족됐고,
#    늘린 자리가 이 파일 한 곳이다. 각 단계는 행동이지 확실성이 아니다(위 표 · D55).
# ✅ 각 단계는 확실성이 아니라 "무엇을 할 것인가"를 뜻한다.
```

## 레이어 / 모듈 분리
의존성은 위→아래 단방향, 역방향 import 금지. 언어마다 이름은 달라도 구조는 동일하다.
```
경계(api/route/handler)
   │
오케스트레이션(application/use-case/service)
   │
계약·모델(domain — 순수, 프레임워크 비의존)
   │
구현체(infra/adapter — 교체 가능)
```
- 교체 가능한 것(엔진·소스·sink·provider·client)은 인터페이스(Protocol/ABC/interface)로 추상화.
- **폴더가 커지면 평평하게 쌓지 않는다.** 오케스트레이션 층은 **기능(도메인) 단위**로 가르고
  공통은 `common/` 한 곳에 둔다 — 기술 종류(`handlers/`·`helpers/`)로 가르면 한 기능이 흩어진다.
- 오케스트레이션은 추상 인터페이스에만 의존. 환경(local/dev/prod) 분기는 factory/DI가 주입.

## 추상화 전략 (코드 작성 전 필수 기술)
1. 어떤 인터페이스를 쓰거나 만드는가.
2. 새 구현체 추가 시 **어떤 파일만** 건드리면 되는가(Open-Closed 검증).
3. 의존성 주입은 어디서 어떻게 일어나는가.

## 재기 전에 고치지 않는다 (성능 개선 · 낭비 제거 · 용량 산정에 한정)
> 버그 수정에는 적용하지 않는다 — 규칙이 짐이 된다.

- **손대기 전에 실물을 잰다.** 계측 없이 고른 표적은 자주 틀린다.
- **표본은 실제 일감의 크기로.** 짧은 표본에서 1순위였던 단계가 실물에서 3순위가 된다.
- **한 지점만 재고 증가율을 단정하지 않는다.** 비중(구성)과 증가율(초선형 여부)은 다른 측정이다 —
  후자는 크기가 다른 두 지점을 견줘야 나온다.
- 사양·동시성 산정은 **버스트(몰린 구간)와 상시 도착률을 갈라서** 낸다. 섞으면 크게 틀린다.

## 설정 (config)
- **설정은 한 곳에서 읽는다.** 코드 곳곳에서 환경변수를 직접 꺼내지 않는다 — 어떤 값이 있는지
  세는 것이 불가능해진다.
- **필수와 선택을 가른다.** 필수가 비면 **기동에서 죽는다.** 조용히 기본값으로 도는 것이
  가장 늦게 발견되는 실패다.
- **기본값에는 근거를 한 줄로** 남긴다(그 값이 어디서 나왔는지 · 무엇을 넘으면 안 되는지).
- **예시 파일(`.env.example`)은 실제로 읽는 키와 동기화한다.** 빠진 항목은 운영자가 **있는 줄도
  모른 채** 기본값으로 배포한다.
- 값이 갈리는 축이 둘 이상이면(환경 × 목적지) **이름에 축을 넣는다.** 한 이름에 두 뜻을 담지 않는다.
- 비밀값은 저장소에 두지 않는다. 필요하면 예시 파일에 **키 이름만** 추가한다.

## 예외 처리 (Reliability)
- 시스템 경계(I/O, 외부 프로세스, 모델 추론, 네트워크)에서만 catch. 내부 로직은 예외 전파(catch-and-ignore 금지).
- 재시도는 백오프 + 최대 횟수 명시, 멱등하게.

### 부분 실패 — 계속 진행이 기본, 삼키는 것은 금지
한 단위(창·세그먼트·청크·항목)가 실패했다고 잡 전체를 죽이면 실패율만 오른다. **계속 진행이
기본**이되 아래 둘은 **실패로 확정**한다.

1. **다음 단계의 입력이 되는 값이 비었을 때** — 뒤 단계가 빈 값 위에서 계속 돌면 결함이 산출물까지 간다.
   (원본 확보 · 미디어 메타 추출 · 받아쓰기 본문 · 산출물 목적지 결정처럼 뒤가 그것을 읽는 자리)
2. **산출물 내용이 달라지는데 그 사실을 산출물에 실을 수 없을 때** — 실을 자리가 있으면
   (품질 표시·결함 목록) 계속 진행한다. **되돌릴 수 없는 자리는 특히 실패로 확정**한다
   (부분 산출물이 완성품처럼 보이는데 원본이 이미 지워진 경우).

계속 진행할 때는 셋을 함께 지킨다.
- **① 센다.** 성공/실패 두 값만 두지 않는다 — **"완료(결함 N건)"** 를 표현할 자리를 만들고
  실패한 단위가 성공 집계에서 빠지지 않게 한다. **실패율 0 이 나오면 좋은 뜻인지 먼저 의심한다.**
- **② 자동으로 닫을 수 있는 것은 닫는다.** 그 단위만 다시 시도하는 층을 먼저 두고 **남은 것만
  사람이 볼 목록**으로 낸다.
- **③ 비율이 임계를 넘으면 잡 실패로 승격**한다. 임계값은 프로젝트가 정한다 —
  한둘은 정상이고 30%는 사고다. 〈〈이 프로젝트의 임계: 값·근거〉〉

## 공통 금지
- 로깅 대신 콘솔 출력 잔존(언어별 파일 참조) / 근거 없는 매직 넘버 / TODO·FIXME 머지 /
  사전 존재 죽은 코드 임의 삭제 / 무단 품질 저하 / 불필요한 과잉 추상화.
- 죽은 코드를 **지우기로 한 경우**: 이름으로 찾으면 오판한다(같은 이름이 산 쪽·죽은 쪽에 다 있다).
  **호출 관계를 그려 도달하지 못하는 것만** 지운다.
