# CLAUDE.base.md — 프로젝트 컨텍스트 베이스 (v1_2025H2)

> **사용법.** 새 프로젝트의 `.claude/CLAUDE.md`는 이 베이스를 복사해 만든다.
> `〈〈 … 〉〉`는 **프로젝트마다 채우는 빈칸**, 나머지(행동 지침 / 운영 정책 / prompt 작성 /
> 커밋 형식 / 버전 조회 / 세션 이력)는 **공통 불변부**로 그대로 둔다.
> `rules/`(공통 + 사용하는 언어 파일)와 `prompts/_TEMPLATE.md`, 필요한 `skills/`를 함께 복사한다.
> (`seed-project-context` skill이 수행.)
>
> 이 베이스는 **자막 제작 생태계**의 실제 프로젝트들에서 반복 검증된 패턴을 일반화한 것이다.
> 자막·화면해설이 주력이지만 그 외 성격의 프로젝트에도 그대로 적용한다.

## 프로젝트 개요

**〈〈프로젝트명〉〉** — 〈〈한 문장 정의: 무엇을 입력받아 무엇을 산출하는 무슨 시스템인가〉〉.

〈〈핵심 파이프라인 / 산출물 요약 (bullet)〉〉

### 생태계에서의 위치  〈〈해당 시〉〉
〈〈다른 자막/화면해설 프로젝트(완료영상 배치 / 실시간 프레임 / 실시간 오디오 등)와의 관계,
무엇과 연계되고 무엇과 별도 진화 라인인지 한 문단. 독립 프로젝트면 생략.〉〉

### 비협상 목표 (왜 양보 불가인가)
〈〈절대 포기 불가한 1~2개 목표와 이유. 예: 저지연·고품질, 인터페이스 안정성. 없으면 생략.〉〉


## 행동 지침  ※ 공통 불변부 (수정 금지)

### 🔒 보안 — 비밀파일 절대 접근 금지 (최우선)
`.env`, `.env.*`(단 `.env.example` 예외), 자격증명·키(`*.key`, `*.pem`, `credentials*`, `*token*`, `secrets*`, `id_rsa*`), 클라우드 인증(`.aws/`, `.ssh/`, `*.kube/config`)은 **열람·복사·내용 인용·로그 출력·커밋 일절 금지.** 값이 필요하면 `.env.example`에 키 이름만 추가하고 실제 값은 사용자가 직접 채우게 한다. 디버깅 중 비밀값이 출력에 섞이면 즉시 마스킹(`<REDACTED>`). `.dockerignore`/`.gitignore`에 위 패턴이 포함됐는지 점검한다.

본 섹션은 [forrestchang/andrej-karpathy-skills](https://github.com/forrestchang/andrej-karpathy-skills)
가이드라인에서 도출. 사소한 작업에는 판단으로 절충하되, 기본 편향은 **속도보다 신중**.

### 1. 코드 작성 전 사고
**가정하지 말 것. 혼란을 숨기지 말 것. 트레이드오프를 표면화할 것.**
- 가정은 명시. 불확실하면 묻는다.
- 여러 해석이 가능하면 제시 — 말 없이 하나 고르지 않는다.
- 더 단순한 접근이 있으면 말하고, 필요하면 사용자 지시도 되묻는다.
- 모호하면 멈춘다. 무엇이 혼란스러운지 이름 붙이고 묻는다.

### 2. 단순함 우선
**문제를 해결하는 최소 코드. 투기적인 것은 금지.**
- 요청하지 않은 기능·"유연성"·"설정 가능성"을 끼워 넣지 않는다.
- 1회용 코드에 추상화를 만들지 않는다.
- 불가능한 시나리오를 위한 에러 핸들링을 추가하지 않는다.
- 200줄 짠 뒤 50줄로 줄일 수 있으면 다시 쓴다.
- **시험:** "시니어 엔지니어가 이거 과하다고 할까?" 그렇다면 단순화.

### 3. 외과적 변경
**필요한 부분만 건드린다. 자신이 만든 흔적만 청소한다.**
- 주변 코드·주석·포맷을 "개선"하지 않는다. 깨지지 않은 것을 리팩터하지 않는다.
- 다르게 짤 거 같아도 기존 스타일을 따른다.
- 무관한 죽은 코드는 발견하면 언급만 — 삭제하지 않는다.
- 본인 변경으로 orphan이 된 import·변수·함수만 제거. 사전 존재 죽은 코드는 명시 요청 없으면 제거 금지.
- **시험:** 변경된 모든 줄이 사용자 요청으로부터 직접 추적되는가.

### 4. 목표 주도 실행
**성공 기준을 정의. 검증될 때까지 루프.**
- 작업을 검증 가능한 목표로 변환("버그 수정"→"버그 재현 테스트 작성 후 통과").
- 가능하면 **측정 가능한 수치 임계값**으로("지연 줄이기"→"5초 청크 추론 p95 < N ms").
- 다단계 작업은 계획부터:
```
1. [단계] → 검증: [측정 가능한 확인]
2. [단계] → 검증: [측정 가능한 확인]
```

## Claude Code 운영 정책  ※ 공통 불변부

작업은 **세션 단위 prompt 파일**(`.claude/prompts/{NN}_{topic}.md`)로 진행한다. 각 prompt는
Claude Code 에이전트가 1 세션에 실행하는 self-contained 작업 지시서다.

- 각 prompt 진입 시 `.claude/rules/`를 **반드시 먼저 읽는다**: `coding/_common.md` + 해당 언어·프레임워크 파일,
  `logging.md`, `docker.md`, `git_workflow.md`, `testing.md` (각 prompt 상단에 명시).
- 꼭지(prompt의 `## 진행 현황` 번호 항목 1개) 단위로 커밋 메시지를 사용자에게 제시하고 승인 후
  다음 꼭지 진행. **세션 전체를 한 번에 커밋하지 않는다.**
- 세션 종료 시 prompt 파일을 `.claude/prompts/_complete/`로 이동 + `SESSION_LOG.md` 표 갱신 + **`harvest-worklog`로 그날 작업을 Vault 업무일지에 환원**.

## Prompt 작성 정책  ※ 공통 불변부

**prompt 파일은 사람이 아니라 Claude가 작성한다.** 사용자가 하려는 작업을 설명하면, Claude가 그것을
`prompts/_TEMPLATE.md` 형식의 1세션짜리 작업 지시서로 변환한다.

### 1세션 분량 기준 (토큰·효율 비례)
한 세션 prompt는 **토큰 예산과 산출 효율이 적절히 비례하는 만큼**만 담는다. 너무 크면 컨텍스트가
흐려지고 후반 품질이 떨어지며, 너무 작으면 왕복 오버헤드가 커진다.

- **분할 신호(이러면 쪼갠다)**: 독립적으로 검증 가능한 꼭지가 **5~7개를 넘어갈 때**, 서로 다른 레이어를
  광범위하게 동시에 건드릴 때, 한 꼭지의 변경 범위가 다음 꼭지의 전제를 통째로 바꿀 때.
- **권장 크기**: 한 세션 = 하나의 응집된 목표 + 그것을 이루는 **3~5개 꼭지**. 각 꼭지는 1 커밋으로 닫힌다.
- **작성 시 Claude가 하는 일**: (a) 작업을 측정 가능한 성공 기준으로 환원, (b) 추상화 전략 1문단,
  (c) 꼭지를 의존 순서로 나열(각 꼭지에 검증 방법), (d) 범위 밖 항목 명시.
- 작업이 1세션을 넘으면 **prompt를 여러 개로 분할 제안**하고 번호(`02_`, `03_`)와 의존 순서를 함께 제시한다.
- prompt가 진행 중 비대해지면 남은 범위를 다음 세션 prompt로 떼어내고 본 prompt의 "범위 밖"으로 이전한다.

## Git 커밋 형식  ※ 공통 불변부
```
type: [커밋 제목]

- 기능 요약 bullet
- 기능 요약 bullet
```
type은 `fix`/`feat`/`refactor`/`chore`/`docs` 중 택일. 제목 50자 이내·현재형·마침표 없음.
**세션 내 각 꼭지 완료 시마다** 커밋 메시지를 출력하고 다음 작업 전 대기.

### 📌 제목·본문 모두 개조식 (명사형) — 서술문 금지
커밋 메시지는 **나중에 `git log --oneline` 으로 훑는 색인**이다. 문장은 끝까지 읽어야 뜻이 잡히고
목록에서 길이가 들쭉날쭉해져 찾기 어렵다. 명사형이면 앞 두세 단어로 판별된다.

- **`~한다`·`~했다`·`~된다`·`~아니다` 같은 문장 종결을 쓰지 않는다.** 명사(`제거`·`유실`·`미생성`)나
  `~기`·`~음`으로 닫는다. 본문 bullet 도 같다.
- **본문은 문단이 아니라 bullet.** 근거·수치가 붙으면 **한 단계 들여쓴 하위 bullet**으로 내린다.
- 제목에 `— 뒤에 이유`·`(괄호에 수치)`를 붙이지 않는다. 그 자리는 본문 bullet 이다.

```
✅  fix: 캐시 키 축 누락으로 재사용이 오답

    - 언어 축이 빠져 다른 언어 실행이 기존 산출물을 재사용
        - 실측 11건 중 2건 해당 · 비용 0원이라 경고도 없었음
    - 키에 언어 추가 + 기존 파일은 이관 없이 폐기

❌  fix: 캐시 키에서 축이 빠지면 재사용이 오답이 된다        ← 서술문 종결

❌  fix: 캐시 키 축 누락 수정

    언어 축이 빠져 있어서 다른 언어로 실행하면 기존 산출물을
    그대로 재사용하는 문제가 있었다. 키에 언어를 추가했다.   ← 문단 + 서술문
```

## 라이브러리 / 버전 정보 조회 지침  ※ 공통 불변부

외부 라이브러리 버전·호환성·최신 API는 **반드시 오늘 날짜 기준으로 검색**한다.
- 쿼리에 현재 연도 명시. cutoff 기준 오래된 정보를 그대로 쓰지 않는다.
- PyPI / GitHub Releases / npmjs / 공식 문서를 1차 출처로.
- 매 세션 진입 시 brave-search 재확인 항목: 〈〈프로젝트 핵심 의존성〉〉.

## 세션 이력  ※ 공통 불변부

각 세션 prompt는 `prompts/{NN}_{topic}.md` 1 파일 단위로 진행, 종료 후 `prompts/_complete/`로 이동.
누적 메타(세션 번호·파일명·변경 요약)는 [SESSION_LOG.md](SESSION_LOG.md)에서 관리.

**변경 요약은 30~40자 이내 개조식 한 줄** — 표는 훑는 색인이다. 근거·수치·경위는 커밋 메시지와
diff 가 진다. 한 줄에 안 담기면 세션을 쪼갠다.
